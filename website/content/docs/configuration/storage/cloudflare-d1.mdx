# Cloudflare D1 storage backend

The Cloudflare D1 storage backend stores OpenBao's data in a Cloudflare D1
database. D1 is SQLite-compatible, so this backend shares OpenBao's generic SQL
storage behavior with the SQLite backend.

:::warning

**No High Availability** – the Cloudflare D1 backend does not support OpenBao
HA locking. Do not configure it as `ha_storage`, and do not set
`ha_enabled=true`.

:::

:::warning

Cloudflare deployments must use static seal configuration with the seal key
provided through the environment. The backend requires `BAO_STATIC_SEAL_KEY` to
be set unless `require_static_seal_env=false` is configured.

:::

```hcl
storage "cloudflare-d1" {
  connection_url = "d1://account_id:api_token@database_id"
}

seal "static" {
  current_key_id = "cloudflare-2026-05"
  current_key    = "env://BAO_STATIC_SEAL_KEY"
}
```

The connection URL can also be provided with `BAO_D1_CONNECTION_URL`; environment
variables take precedence over values in the configuration file.

## `cloudflare-d1` parameters

- `connection_url` `(string: <required>)` – Cloudflare D1 connection URL in the
  format `d1://account_id:api_token@database_id`. This can also be set with the
  `BAO_D1_CONNECTION_URL` environment variable.

- `table` `(string: "openbao_kv_store")` – Specifies the name of the table in
  which to write OpenBao data. OpenBao will attempt to create it if missing and
  `skip_create_table=false` (the default).

- `skip_create_table` `(string: "true|false", default "false")` – When enabled,
  OpenBao will not attempt to automatically create database tables if missing.

- `require_static_seal_env` `(string: "true|false", default "true")` – When
  enabled, startup fails unless `BAO_STATIC_SEAL_KEY` is present in the
  environment.

- `ha_enabled` `(string: "false")` – Must not be set to `true`; Cloudflare D1
  does not support OpenBao HA locking.

## `cloudflare-d1` examples

Using environment variables:

```shell
export BAO_D1_CONNECTION_URL="d1://account_id:api_token@database_id"
export BAO_STATIC_SEAL_KEY="32-byte-hex-or-base64-static-seal-key"
```

```hcl
storage "cloudflare-d1" {}

seal "static" {
  current_key_id = "cloudflare-2026-05"
  current_key    = "env://BAO_STATIC_SEAL_KEY"
}
```

## Listing nested secrets

Paths are prefixes, not directory records. A secret such as `staging/private`
can coexist with `staging/private/app/deployment`. Deleting the exact parent
secret does not delete its descendants. Both regular and paginated listings
continue to show `private/` while any descendant exists, even if no parent
secret was ever written. Prefix matching is case-sensitive and treats `%`, `_`
and other characters literally.

Older D1 backend builds listed only immediate parents. Deleting a parent
secret could therefore hide deeper descendants from ancestor listings without
deleting their stored values. Upgrade the OpenBao server to a build containing
the descendant-listing fix; no schema change, secret rewrite or placeholder
creation is required. Existing flat public/private secrets and initialization
commands continue to work unchanged.

To investigate a missing listing, check an exact known secret path and its
KV metadata before taking recovery action. A soft-deleted KV v2 version can be
undeleted; destroyed versions or deleted metadata require a separate backup.
A recursive delete operation still deletes the selected descendants.
